# Contributing to Ronoid Core

Thank you for helping test Ronoid Core.

The most valuable contributions are **evidence**, not agreement.

We welcome:

- concrete failure cases,
- adversarial examples,
- bypass attempts,
- implementation reports,
- test cases,
- edge cases,
- comparisons with established AI governance and security frameworks,
- corrections to ambiguous or contradictory requirements.

## Ground rules

1. Do not treat Ronoid Core as a certified safety system.
2. Clearly separate observed behavior from opinion.
3. Include enough context for another reviewer to reproduce the reasoning.
4. Prefer the smallest test case that demonstrates the issue.
5. Do not submit private, confidential, personal, or unlawfully obtained information.

## How to contribute

For a review case, use the format in [EXTERNAL_REVIEW.md](./EXTERNAL_REVIEW.md).

For specification changes, explain:

- the failure being addressed,
- the relevant current rule(s),
- the proposed change,
- expected PASS/REVIEW/FAIL or ALLOW/HUMAN_REVIEW/VETO behavior,
- any new trade-offs introduced.

Ronoid Core is intentionally revision-friendly. A result that disproves part of the framework is useful evidence.
